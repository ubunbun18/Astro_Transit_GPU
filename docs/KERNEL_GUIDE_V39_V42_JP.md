# AstroTransit-GPU カーネルガイド: V39 vs V42

AstroTransit-GPU には、目的の異なる 2 つのハイエンドカーネルが搭載されています。本ドキュメントでは、それぞれの特徴と使用上の注意点を説明します。

---

## 1. V39 "Apex Predator" (超高速スクリーニング用)

V39 は、Blackwell 世代以降の GPU アーキテクチャで理論限界のスループットを叩き出すために設計された、**「速度至上主義」**のカーネルです。

### 特徴
- **並列処理の極致**: ビニング、累積和、探索の全工程を完全に並列化しています。
- **Fast Math**: `rsqrtf` などの非 IEEE 754 準拠の高速演算命令を使用し、演算サイクルを極限まで短縮しています。
- **非決定論的実行**: アトミック演算（`atomicAdd`）を使用するため、浮動小数点の加算順序が実行のたびに微妙に異なり、結果にビットレベルの差異が生じることがあります。

### 注意点
- **数値的パリティ**: Astropy (CPU) との結果の相関係数は約 **0.99〜0.999** です。大規模なスクリーニングには十分ですが、厳密な科学的検証には不向きな場合があります。
- **オーバーサンプリング**: 固定ビン方式に近い挙動をするため、極端なパラメータ設定では Astropy とピークの位置がずれる可能性があります。
- **ビン数の固定**: 実行速度を優先するため、ビン数（`N_BINS`）がコンパイル時に固定されています。動的なビン数変更には対応していません。
- **共有メモリの急増**: 1ブロックで16周期を並列処理するため、ビン数を増やすと共有メモリ消費が V42 の 16 倍の速度で増加します。

---

## 2. V42 "Apex Parity" (厳密検証・論文用)

V42 は、Astropy の C 実装（BoxLeastSquares）とビットレベルで結果を一致させるために設計された、**「精度至上主義」**のカーネルです。

### 特徴
- **完全一致 (Parity 1.0)**: Astropy と全く同じ順序で浮動小数点の加算を行うため、相関係数 **1.000...** を保証します。
- **動的ビニング**: 周期ごとにビン数を動的に再計算する Astropy のロジックを忠実に GPU 上で再現しています。
- **高精度演算**: IEEE 754 に準拠した演算を行い、必要箇所では `double` 精度を維持します。

- **共有メモリ制限**: 広レンジ（10日以上の周期など）で探索する場合、共有メモリ容量が不足し `CUDA_ERROR_INVALID_VALUE` が発生する可能性があります。詳細は「5. ビン数と共有メモリに関する重要な制限」を参照してください。

---

## 3. カーネル比較表

| 項目 | V39 "Apex Predator" | V42 "Apex Parity" |
| :--- | :--- | :--- |
| **設計思想** | 速度とスループットの最大化 | 科学的再現性と完全一致の追求 |
| **推定速度** | ~500 LC/s (超高速) | ~20 LC/s (中速) |
| **Astropy 一致度** | 高い (相関 > 0.99) | **完全 (相関 1.0)** |
| **ビニング方式** | 並列 (atomicAdd) | **逐次 (Thread-0 Sequential)** |
| **ビン数設定** | **コンパイル時固定 (通常 128-256)** | **実行時可変 (動的ビニング)** |
| **主な用途** | 全天サーベイ、初期候補抽出 | 最終確認、論文用データ生成 |

---

## 4. 推奨されるワークフロー

1. **第1段階 (Screening)**:
   `V41` または `V39` を使用して、数百万個のターゲットから可能性のあるトランジット候補を高速に抽出します。
   
2. **第2段階 (Validation)**:
   抽出された候補に対して `V42` を使用し、既存の CPU 実装 (Astropy) と同じ結果が得られることを確認し、科学的な信頼性を担保します。

## 5. ビン数と共有メモリに関する重要な制限 (特に V42)

V42 カーネルは、各周期ごとに GPU の共有メモリ（Shared Memory）上にビンを確保します。このため、探索パラメータによって以下の物理的制限を受けます。

### ビン数の計算式
探索に使用されるビン数 `N_bins` は以下の式で決定されます：
```text
N_bins = (period / (min_duration / oversample)) + oversample
```
例：`period=10.0`, `min_duration=0.01`, `oversample=10` の場合
`N_bins = (10.0 / 0.001) + 10 = 10,010 ビン`

### メモリ消費量と限界
- **V42 (Parity)**: 1ビンあたり **16バイト** (`double` 精度でカウントとフラックスを保持) を消費します。
- **GPU 制限**: 多くの GPU（RTX 30/40/50 シリーズなど）では、1ブロックあたりの共有メモリ上限が **約 100 KB** です。

| ビン数 | V42 メモリ消費 | 判定 |
| :--- | :--- | :--- |
| 2,000 | 32 KB | 安全 |
| 5,000 | 80 KB | **限界付近 (推奨上限)** |
| 10,000 | 160 KB | **エラー (実行不可)** |

### V39 (Apex Predator) の特殊な制限
V39 は 1 ブロック内で 16 ワープレベルの並列化（16 周期同時処理）を行っているため、ビン数に対するメモリ消費が非常に敏感です。

- **メモリ計算式**: `16 (warps) * N_bins * 8 (bytes) = 消費メモリ`
- **限界**: V39 においてビン数を 1,000 以上に設定することは、共有メモリ制限により事実上不可能です。
- **設計思想**: V39 は「少ないビン数で圧倒的な周期数を掃引する」ことに特化しています。

### エラー（CUDA_ERROR_INVALID_VALUE）への対策
長周期のデータを高い解像度（小さい `min_duration` や大きい `oversample`）で解析しようとすると、共有メモリ不足でエラーが発生します。その場合は以下の調整を行ってください：

1. **`min_duration` を大きくする**: ビン数が劇的に減少します。
2. **`oversample` を小さくする**: 解像度は下がりますが、メモリ消費が抑えられます。
3. **高速モード（V39/V41）を検討する**: V39 や V41 といった高速モードは、1ビンあたりのメモリ消費が V42 の半分（`float` 精度）であり、かつ動的ビニングを行わないため、メモリ制限に対してより寛容です。
